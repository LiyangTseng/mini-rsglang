sse.rs: SseLineSplitter keeps a byte buffer. `push` appends a chunk, splits on newline (0x0A), and strips one trailing 0x0D. For each complete line starting with `data: `, it yields `SseData::Done` when the rest is exactly `[DONE]`, and otherwise `SseData::Payload(rest)` (lossy UTF-8). Blank lines, `:` comments and other fields are ignored. Partial lines stay buffered. `finish` processes a final unterminated line the same way. Hand-written per CLAUDE.md, because eventsource-stream is unmaintained and `/generate` uses single-newline framing.

client.rs: `local_base_url(port)` returns `format!("http://127.0.0.1:{port}")`, and there is deliberately no host parameter anywhere in the crate (T-02-11 precedent, T-07-03). `build_client()` uses `reqwest::Client::builder()` with `.no_proxy()`, `.tcp_nodelay(true)` and `.read_timeout(Duration::from_secs(300))`. No total timeout: long generations must not be cut. `fetch_model_id` sends GET `{base}/v1/models` and returns `data[0].id`, with a clear error if it is missing. `stream_chat` takes `t_send_unix_ns` from SystemTime and an Instant before the POST to `{base}/v1/chat/completions`, with exactly the Phase 2 body above. In this task, only the `CancelPlan::None` path has to be complete; Task 2 completes the cancel paths. The response is read with `Response::chunk()` in a loop. TTFT is taken at the first Payload. ITL is the gap between consecutive Payloads. `Done` ends the request as Completed, and EOF ends it as Completed too (Phase 2 rule). A non-200 status gives Failed with error `status <n>`. A transport error gives Failed with its message. e2e is measured to the last byte read.

metrics.rs: each histogram uses `Histogram::<u64>::new_with_bounds(1, HIST_MAX_US, 3)`. `record` handles TTFT for Completed or Cancelled requests that have a ttft, ITL gaps for the same requests, and E2E for Completed requests only. Values are microseconds, clamped to [1, HIST_MAX_US]. `percentile_ms` returns None for an empty histogram; otherwise it returns `value_at_quantile(q) / 1000.0`. `summary` fills p50/p90/p99/max for TTFT, ITL and E2E.

procs.rs: `ensure_port_free` tries `TcpStream::connect_timeout(127.0.0.1:port, 200 ms)`. If the connect succeeds, it returns Err `port <p> already in use`. This stops a stale server from ever being measured as an arm (T-07-15 seam). `launch` calls ensure_port_free and opens the log file in append mode. It spawns `std::process::Command` from argv[0] with the remaining args, `CommandExt::process_group(0)`, stdin null and stdout/stderr going to the log file, and applies env_set/env_remove. It records `pgid = leader_pid = child.id()`. `wait_ready` polls GET `/v1/models` at the poll interval until it gets a 200, and returns the elapsed time since `launched_at`. It fails early with a tail of the log if `leader_exited(handle)`, and fails on timeout. `leader_exited` uses sysinfo: the leader is absent or `ProcessStatus::Zombie`. It never calls `try_wait`/`wait`, because reaping would free the pgid number. `teardown` sends `killpg(SIGINT)` and polls `group_members_alive` every 100 ms up to the grace period. Then it sends `killpg(SIGKILL)` if any member is still alive. Only after that does it reap the leader with `wait()` and report survivors. `group_members_alive(pgid)` refreshes sysinfo processes and returns the pids that are not zombies and whose `nix::unistd::getpgid(Some(pid))` equals pgid. Task 2 adds the pgid guards and the Drop guard on top of this.

bin/bench-stub.rs: a clap CLI with the flags in the interface list (this task needs only --port, --ttft-ms, --itl-ms and --model-id to work). It runs a tokio TcpListener on 127.0.0.1 only (T-07-04), never 0.0.0.0. It reads each request head up to the blank line, reads a Content-Length body, and routes:
- GET /v1/models: `{"object":"list","data":[{"id":<model-id>,"object":"model"}]}`
- GET /health: 200 ok
- POST /v1/chat/completions: parses `max_tokens` (default 16) from the JSON body. It immediately writes and flushes `HTTP/1.1 200 OK`, `Content-Type: text/event-stream`, `Cache-Control: no-cache` and `Connection: close` headers, then the blank line. After `--ttft-ms`, and then every `--itl-ms`, it writes one `data: {chunk json}` line followed by a blank line, `max_tokens` times. The last chunk carries `finish_reason` `length`. Then it writes `data: [DONE]`, closes, and prints `stub-event kind=done id=<n> tokens=<k>`.
- Anything else: 404.
Every response carries `Connection: close`. It prints `stub-event kind=ready port=<p>` once bound. Request ids count from 0.
