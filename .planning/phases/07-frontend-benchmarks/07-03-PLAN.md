<objective>
Build the BENCH-06 "standard inference" workload driver. Per D-12, it reuses bench_simple.py's client-helper shape, the same shape Phase 2 adapted for its Scenario 2 driver, instead of defining a new workload. It writes a JSON result that the Rust orchestrator (plan 07-09) treats as one A/B trial.

Purpose: BENCH-06 asks whether the Rust frontend regresses standard throughput relative to Python. "Standard inference" then means upstream's own benchmark everywhere in the project, run unchanged against both servers (CLAUDE.md parity row), with the only differences being a configurable port, a JSON output and an explicit RNG draw order.

Output: python/rsglang/bench/{__init__,standard_throughput}.py and python/tests/test_bench_simple_reuse.py.

Design notes:
- bench_simple.py hard-codes PORT 1919 and only logs its stats. This module takes `--port`, computes the same statistics with upstream's formulas and writes them as JSON.
- bench_simple interleaves its prompt-generation RNG draws with an asyncio task, so their order depends on scheduling. This module draws in a fixed order: the warm-up prompt, then the 64 prompt lengths and prompts, then the 64 output lengths. That keeps the workload identical for both frontends at a given seed, which is what the A/B comparison needs.
- The JSON carries wall-clock `t_start_unix` and `t_end_unix` around the measured batch, so the orchestrator can attribute GC pauses and memory to that window (BENCH-08).
</objective>
