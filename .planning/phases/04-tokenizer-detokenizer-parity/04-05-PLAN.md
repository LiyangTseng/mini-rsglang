<task type="auto">
  <name>Task 2: Wire D-04's clean-skip behavior into the main CLI</name>
  <files>scripts/gen_tokenizer_fixtures.py</files>
  <read_first>scripts/gen_tokenizer_fixtures.py (the `generate()`/`check()`/`main()` functions created in Plan 04-01 — currently all-or-nothing `EnvError` on any failure, mirroring `gen_wire_fixtures.py`'s model which has no notion of a partially-unavailable oracle); CONTEXT.md D-04 ("if HF_TOKEN/gated access is unavailable... Llama parity tests skip cleanly with a clear log. Qwen3-0.6B parity... always runs regardless").</read_first>
  <action>
Define a `GatedAccessError(Exception)` class, distinct from `EnvError`, raised by
`minisgl.utils.hf.load_tokenizer` failures that are specifically auth/gated-access shaped (catch the
underlying `huggingface_hub` exception type raised for a 401/403 and re-raise as
`GatedAccessError(repo_id, detail)` — do not catch every exception, only the auth-shaped one, so a
genuine bug elsewhere still surfaces as a hard failure). In `gen_tokenizer_fixtures.py`'s
`generate(out_dir)` loop over `MODELS`, wrap each model's `load_tokenizer(spec.repo_id)` call: for a
non-gated model (`spec.gated is False`, i.e. Qwen3), let any failure propagate as a hard `EnvError`
(unchanged — Qwen3 parity always runs, per D-04); for a gated model (`spec.gated is True`, i.e.
Llama) whose call raises `GatedAccessError`, print `SKIP {model.slug}: gated access unavailable
({detail})` to stderr, skip writing that model's fixtures for this run, and continue to the next
model — do not raise, do not affect the function's return code. Apply the same per-model skip logic
inside `check(out_dir)`'s regenerate-and-diff loop: a skipped model's existing committed fixtures are
left untouched and not diffed (neither a false "missing" nor a false "stale" report), while every
other model's diff logic is unchanged. Confirm `main()`'s exit code is still 0 when Qwen3 succeeds
and Llama is cleanly skipped, and still 2 only on a genuine `EnvError` (e.g. Qwen3 itself failing, or
a non-auth-shaped exception from `load_tokenizer`).
  </action>

    <automated>HF_TOKEN= .venv/bin/python scripts/gen_tokenizer_fixtures.py --check 2>&1 | tail -10; echo "exit=$?"</automated>
    <fails_when>the printed exit code is not 0, or stderr contains no "SKIP llama-3.2-1b-instruct" line</fails_when>
  </verify>
  <done>Running the generator with `HF_TOKEN` unset prints a clear "SKIP llama-3.2-1b-instruct" message, still validates Qwen3's fixtures, and exits 0 — never aborting the whole run over Llama's unavailability.</done>
