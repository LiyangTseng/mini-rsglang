  <behavior>
- Given decoded text with `" ."`, `" ?"`, `" !"`, `" ,"`, `" ' "`, `" n't"`, `" 'm"`, `" 's"`, `" 've"`, `" 're"` substrings and `clean_up_tokenization_spaces: true`, the chain produces the exact punctuation/contraction-adjusted output `transformers`' own staticmethod would, applying all 10 replacements in order on the cumulative result.
- Given the same input but `clean_up_tokenization_spaces: false` (Qwen3), no replacement chain runs and the text passes through unchanged — this must not regress Plan 04-03's Qwen3 behavior.
- Given a Llama chat-template-rendered prompt's encoded `input_ids`, a helper counts how many elements equal the model's `bos_token_id`.
  </behavior>
  <action>
In `detokenize.rs`, implement `fn clean_up_tokenization(text: &str) -> String` as the exact ordered
chain: replace `" ."`→`"."`, `" ?"`→`"?"`, `" !"`→`"!"`, `" ,"`→`","`, `" ' "`→`"'"`, `" n't"`→`"n't"`,
`" 'm"`→`"'m"`, `" 's"`→`"'s"`, `" 've"`→`"'ve"`, `" 're"`→`"'re"`, each `.replace()` applied to the
PREVIOUS step's result (not all on the original string independently). Wire it into `Detokenizer::step`:
after computing `output_str`'s newly-decoded text (both the normal-append branch and the
`find_printable_text` fallback branch), apply `clean_up_tokenization` to that text when
`self.clean_up_tokenization_spaces` is true, before appending to `decoded_str`/computing the
incremental output — this must not change Qwen3's existing Plan 04-03 test results, since Qwen3's
`clean_up_tokenization_spaces` is `false`.

In `encode.rs`, add `pub fn count_bos_occurrences(ids: &[u32], bos_token_id: Option<u32>) -> usize`
(returns 0 if `bos_token_id` is `None`, else counts matching elements). Do not add any
de-duplication logic that removes a BOS token `encode_prompt` produces — this function is purely
diagnostic/assertive, consumed by Task 2's test, never by production encoding logic.
  </action>
