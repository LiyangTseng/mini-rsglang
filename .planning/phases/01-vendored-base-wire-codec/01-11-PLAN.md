Close gaps G-01-7-WR04 and G-01-7-WR01 (code-review findings WR-04 and WR-01 in the first 01-REVIEW.md, commit 261f8ee). The user triaged both as fix-now in UAT test 7.

Root causes, re-verified in code at b15a8fd:
- WR-04 (crates/rsg-server/src/handshake.rs:18-26): the doc comment says every key is required and only eos_token_id may be null. serde's derive treats a missing `Option<T>` field as None even with deny_unknown_fields, so a launcher bug that drops the key is logged as eos_token_id=null and accepted instead of exiting 2. missing_key_is_malformed removes only num_pages, so it does not catch this.
- WR-01 (python/rsglang/launch.py:101, 123): the guard is the literal check `"--shell-mode" in rest`. Upstream's parse_args uses argparse's default allow_abbrev=True; `--shell-mode` is its only option starting with `--s`. So `--shell` or `--shell-m` turns on shell mode, and upstream rewrites max_running_req=1, cuda_graph_max_bs=1 and silent_output=True. Line 123 then discards the returned run_shell, and rust mode runs silently with those limits, which would corrupt any benchmark.

Purpose: D-11 makes the handshake a strict contract (every key present), and D-05's rust mode must never run with shell-mode limits. Both guards must hold however the input is malformed or spelled.
Output: a required-but-nullable eos_token_id with unit and CLI tests, the parsed run_shell check with a parametrized test, and WR-01/WR-04 marked fixed.
</objective>
