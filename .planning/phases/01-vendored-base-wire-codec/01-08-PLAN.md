<objective>
Close gap G-01-3 (code-review finding WR-02): the scheduler's parent-death watchdog must not miss a launcher that dies early, so `kill -9` of the launcher never leaves an orphaned (on the GPU box: GPU-holding) scheduler.

Root cause (binding, from .planning/debug/wr02-watchdog-late-ppid.md): python/rsglang/backend.py start_parent_watchdog() takes its reference pid from os.getppid() when run_scheduler starts. Under the forced spawn start method (launch.py), run_scheduler only starts after the child has booted a fresh interpreter, re-imported rsglang.launch as __mp_main__ and unpickled ServerArgs (importing torch, minisgl.utils.hf, minisgl.server.launch): about 2.2-2.6 s on the Mac, longer with CUDA torch. A launcher SIGKILLed (pid only) inside that window has already reparented the child, so the watchdog records ppid 1 (or a subreaper) as "the parent" and never fires. The launcher pid is never passed, and no PR_SET_PDEATHSIG is used. rsg-server is not affected (its stdin-EOF rule is level-persistent).

Purpose: D-12's no-orphan backstop must hold for a launcher death at any moment, not only after the handshake. The existing e2e test and GPU step 4 both kill after the handshake, outside the window, so they pass with the bug present.
Output: explicit launcher pid from launch.py to backend.py, a watchdog that re-checks immediately and arms PR_SET_PDEATHSIG on Linux, an early-kill e2e test, watchdog unit tests, GPU step 4b, and WR-02 marked fixed.
</objective>
