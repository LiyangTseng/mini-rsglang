<objective>
Close gap G-01-2 (code-review finding CR-01): a group SIGINT (terminal Ctrl-C, or `kill -INT -- -<pgid>`) to the rust-mode launcher must exit 0 with no failure report, before and after the backend is ready.

Root cause (binding, from .planning/debug/cr01-group-sigint-exit-1.md): both rust-mode loops in python/rsglang/launch.py check stop_requested only at the top of each iteration. The SIGINT/SIGTERM handler only sets a flag, and PEP 475 retries the interrupted ready_queue.get until its full 0.5 s / 0.2 s timeout. By the time the loop body runs, the children have already reacted to the same group signal: rsg-server has exited 0 (its contractual signal code, or -2 if still booting), or a pre-ready scheduler has posted a KeyboardInterrupt error envelope. The body classifies that as a failure and calls shutdown(1), so the launcher exits 1.

Purpose: D-12 says a stop signal tears the run down cleanly and exits 0. Any harness that stops rust mode the way scripts/gpu_phase1_check.sh stops python mode (a group SIGINT) currently sees a spurious failure.
Output: the stop re-check in launch.py, a status marker in the fake scheduler's hang mode, three group-SIGINT e2e tests, and CR-01 marked fixed in 01-REVIEW-DISPOSITION.md.
</objective>
