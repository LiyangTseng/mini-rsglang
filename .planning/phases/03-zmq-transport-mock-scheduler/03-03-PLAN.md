<objective>
Give mock-scheduler the backend misbehaviors that the Phase 5 cancellation tests need (MOCK-01, success criterion 3), each with its own test:
- late tokens after an abort;
- silently dropped overlong prompts;
- several requests' replies batched into one message.

Purpose: Phase 5 (LIFE-02/LIFE-04) and the 03-06 end-to-end test have to provoke these behaviors on purpose. D-09 fixes how they are configured:
- CLI flags at spawn;
- behaviors scoped to specific uids through uid-range flags, so one process can run several behaviors at once;
- a fixed `--batch-size N` with a short flush timer.

D-10 keeps timing to fixed delays. D-11 defers richer timing, so this plan adds no randomness, seeds, per-uid delays or scenario files.

Output: the extended `src/bin/mock-scheduler.rs` and `tests/mock_scheduler_behaviors.rs`.

Vocabulary (Claude's discretion per CONTEXT, kept to the D-09 example syntax):
- `--misbehave-uids <LIST> --behavior <late-abort-token|drop-overlong>`, repeatable and paired by position.
- LIST is comma-separated uids or inclusive ranges `A-B`.
- Batching is global (`--batch-size`), not per uid, because D-09 specifies one fixed batch size.
- The upstream overlong rule (input_len >= max_seq_len is dropped, otherwise max_tokens is clamped) applies to every uid. The mock advertises max_seq_len in its handshake, and the real scheduler behaves exactly this way. `drop-overlong` lets a test trigger the same silent drop on chosen uids without building an oversized prompt (D-09: "a third triggers the overlong-prompt drop").
</objective>

## Flagged assumptions (unresolved edge probe)

- **MOCK-01, edge category "unclassified — review manually" (status: unresolved; never auto-resolved).** The deterministic edge probe could not classify MOCK-01. Below is the planner's own reading of the edges this mock leaves open. The probe has not verified it, and the phase verifier should confirm or reject it:
  1. A uid flagged for a behavior that is never submitted (or never aborted, for late-abort-token) never triggers that behavior. The mock does not report unused flags. Tests always exercise the uids they flag.
  2. A second UserMsg for a uid that is still running replaces that request and logs a warning (03-01). The real scheduler would admit a duplicate request. Phase 5 is responsible for unique uids.
  3. late-abort-token emits its late tokens only for a uid still running when the abort arrives. An abort that arrives after the uid has finished produces nothing, matching the real scheduler's no-op on unknown uids.
