<objective>
Prove criterion 3 (LIFE-03): 128 concurrent requests with random cancellations against the mock end with no leaked requests, no stuck connections, and exactly one terminal state each. Measure the non-streaming disconnect bound that D-03 accepts, and close LIFE-04 on the chat route (504 on backend silence, 400 on overlong, no fake "complete" stream).

Purpose: plans 05-01 and 05-04 prove each lifecycle path in isolation. This plan proves them together under concurrency, where races (cancellation versus finish, late tokens versus new uids) actually happen.

Output: `tests/http_nonstream.rs`, `tests/stress_128.rs`, an open-file-limit line in `scripts/check_all.sh`, and any driver fix the stress test forces in `engine.rs`.

Scope (D-04): the stress test is minimal and Phase-5-only. It reuses mock-scheduler's existing fixed-delay and misbehavior flags. The randomized abort-after-N-tokens logic lives in the test driver, not in the mock. It uses a small seeded PRNG written in the test file, with no new crate, and records no latency histograms. Phase 7 builds its own instrumented load generator, unconstrained by this file. The test is fast (seconds, against zero-ish mock delays), so it runs in the default `cargo test` suite, and therefore in check_all, instead of behind `--ignored` as RESEARCH's map suggested: a stronger gate at negligible cost.
</objective>

Server: a TestServer with mock args `--prefill-delay-ms 5 --decode-delay-ms 2 --batch-size 4 --misbehave-uids 0-100000 --behavior late-abort-token` and TestConfig default (Immediate, 5000 ms timeout). Every aborted uid therefore also produces late tokens, and replies arrive batched.

Agents: spawn 128 tokio tasks into a JoinSet. Agent a makes 2 requests in sequence, with a random think time of 0-20 ms before each. For each request, draw:
- endpoint, uniformly from /generate, chat stream, chat non-stream;
- max_tokens, uniformly in 1..=32;
- a unique ASCII prompt `a{a}-r{r}-x`;
- mode: complete (50%), disconnect after k data chunks with k uniform in 0..max_tokens (35%; for non-stream, disconnect after a random 0-40 ms), or disconnect right after the request bytes are written (15%).
The expected echo for a request is its rendered prompt bytes cycled to max_tokens: for /generate the prompt itself, for chat `user: <prompt>\n`. All of it is ASCII, so each token is one char.

For complete mode, assert:
- /generate: the data lines equal the expected echo char by char, then `data: [DONE]\n`;
- chat stream: every chunk's id is the same `cmpl-<n>`, the concatenated delta contents equal the expected echo, and the stream ends with the stop chunk and `data: [DONE]\n\n`;
- chat non-stream: status 200, and `choices[0].message.content` equals the expected echo.
Count completions, disconnects and immediate drops.

Wrap the whole JoinSet drain in `tokio::time::timeout(Duration::from_secs(60))`. A timeout fails the test as a stuck connection; a panicked agent fails it too.

After the agents, call `snapshot_when_idle(Duration::from_secs(10))` and assert:
- active 0, failed 0, invalid_transitions 0;
- received == finished + cancelled;
- finished >= completed-mode count;
- received >= completed-mode count + disconnect-after-k count (requests whose headers or partial body arrived certainly got a uid).
Then poll `mock.observed()` (deadline 5 s) until #Submit == finished + #Abort, and assert no uid has two Submit lines and every Abort uid has an earlier Submit for the same uid.

Finally, one /generate `{"prompt":"after","max_tokens":3}` completes with `data: [DONE]\n` (the server is not wedged). Print one summary line, `stress_seed=<hex> requests=<n> finished=<n> cancelled=<n> aborts=<n> (correctness check against the Mac mock; not performance evidence)`.
