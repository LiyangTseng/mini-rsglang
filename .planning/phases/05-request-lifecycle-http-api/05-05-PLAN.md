<objective>
Capture the parity oracle for API-01 the way D-02 decided: golden fixtures recorded from a live run of upstream's frozen Python frontend against the mock-scheduler, not a hand-port. The Rust side (plan 05-09) replays the same requests and byte-diffs.

Purpose: API-01 says the Rust endpoints must behave identically to the Python frontend, including response format and SSE framing. Upstream's real FastAPI/Starlette/uvicorn stack decides details no reading of api_server.py can settle with certainty: content-type charset suffixes, compact-JSON spacing, HEAD/OPTIONS handling, validation status codes. Recording it live removes the guesswork, the same pattern as Phase 1's `gen_wire_fixtures.py`.

Output: `python/rsglang/testing/python_frontend.py` (runner), `scripts/gen_api_fixtures.py` (generator with `--out` and `--check`), committed `fixtures/api/`, and Python tests.

Design:
- The runner reproduces `minisgl/server/launch.py`'s `start_subprocess` without the scheduler-rank processes (the mock-scheduler binary stands in for the scheduler on the same ipc addresses), then calls upstream's own `run_api_server`. Nothing in upstream's frontend code is replaced or patched.
- Model: `Qwen/Qwen3-0.6B`, the hard-gate model; tokenizer files only, no weights. `--dtype bfloat16` avoids loading config.json for dtype detection, as test_launch_rust_e2e.py does.
- Mock flags: `--prefill-delay-ms 0 --decode-delay-ms 0 --max-seq-len 4096`. The mock echoes prompt token ids, so the output text depends only on tokenization and detokenization: exactly the parity surface.
- One fresh frontend per capture, with requests sent one at a time, so uids (visible in `cmpl-<uid>` and `chatcmpl-<uid>`) are deterministic: 0..9 for the uid-consuming cases.
- Parity scope recorded per case: `compare: "bytes"` means status, content-type and normalized body bytes; `compare: "status"` means status only. Status-only is used for the 422/500 error cases, whose bodies are FastAPI's own validation and error formats and are not claimed by API-01. Other headers (date, server, content-length versus chunked) are out of scope.
</objective>
