  <action>
Create tests/api_parity.rs with `api_parity_matches_python_frontend_fixtures`, multi_thread.
1. Read `fixtures/api/manifest.json`, at `concat!(env!("CARGO_MANIFEST_DIR"), "/../../fixtures/api")`, into a `serde_json::Value`.
2. Spawn `MockScheduler::spawn` with the manifest's `mock_args` and call `wait_ready`.
3. Spawn `RsgServer` with `--backend-addr <mock.backend_addr> --backend-role connect --detok-addr <mock.detok_addr> --detok-role bind --model <manifest.model> --run-id .rsg=parity --host 127.0.0.1 --port 0`. Send the mock's handshake line and poll /health/ready until 200.
4. For each case in order, send exactly the case's method and path, with the `request_body` string's UTF-8 bytes as the body when present (`Content-Type: application/json`), or no body. Collect mismatches instead of stopping at the first one:
   - The status must equal the case's `status`.
   - If `compare == "bytes"`: the response content-type header must equal `content_type` exactly. The body, after applying the same `created` normalization when `normalize` contains "created" (exactly one `"created":<digits>` occurrence replaced with `"created":0`, with the original value within 86400 s of the test clock), must equal the `.body` file byte for byte.
   - A mismatch records the case name, the expected and actual status or content-type, and for body mismatches the first differing byte offset with up to 80 bytes of context on each side, rendered with escape_debug.
5. At the end, assert the mismatch list is empty and print every entry. Send SIGTERM to rsg-server.

Run it. For each mismatch, find the cause in the Rust route (framing, JSON spacing or escaping, field order, header value, status mapping, uid numbering) and fix it in the corresponding src/http file, so Rust matches the recorded Python bytes. The captured Python behavior is the specification (D-02). Re-run until all 18 cases pass. Record every fix, with the case that exposed it, in the SUMMARY.

Never edit fixtures/api by hand, never regenerate them to match Rust, and never change a case's compare mode or normalization. If a divergence comes from the tokenizer or detokenizer (wrong text, not wrong framing), that is a Phase 4 parity bug: stop and report it with the case name instead of patching around it in http/.
