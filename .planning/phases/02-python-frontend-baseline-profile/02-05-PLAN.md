<objective>
Implement the pure analysis layer that turns py-spy speedscope files, hook JSONL records and request timing records into the exact per-scenario metric blocks of the sidecar schema.

Purpose: this is where BENCH-01's numbers are defined. It covers the radix-cache share of scheduler time (D-09 frames, D-10 denominator), per-process CPU and GIL-held fractions and IPC/serialization cost per request (D-01, D-04), GC pause statistics and their overlap with P99 TTFT spikes (D-03), and memory growth summaries (D-02). All of it is pure functions with exact boundary and precision contracts, test-driven on the Mac. RESEARCH Pitfall 1 means there is no cross-process GIL "contention" number to compute. The honest metric is the per-process GIL-held fraction, plus the tokenize/detokenize split inside the one tokenizer process. The report (02-09) explains that framing.
Output: python/rsglang/profiling/analysis.py and python/tests/test_profile_analysis.py.

<interfaces>
py-spy 0.4.x speedscope output (read from github.com/benfred/py-spy src/speedscope.rs this session): top-level keys "$schema", "profiles", "shared", "activeProfileIndex", "exporter", "name". There is one profile per (pid, thread id), each {"type":"sampled","name":<thread name>,"unit":"seconds","startValue":0.0,"endValue":len(samples)/rate,"samples":[[frame index, ...]],"weights":[1/rate per sample]}. shared.frames entries are {"name","file","line","col"}. Each sample lists frame indices root-first. Without --idle, only non-idle samples are recorded; with --gil, only samples whose thread holds the GIL.

Hook records (02-02): gc {"kind":"gc","pid","t","duration_s","generation","collected","uncollectable"}, where t is perf_counter at GC stop, so the pause interval is (t - duration_s, t). mem {"kind":"mem","pid","t","traced_current","traced_peak"}. alloc_top {"kind":"alloc_top","pid","t","tag","sites":[...]}.

Request records come from plan 02-06's RequestRecord. analysis.py duck-types them and never imports scenarios.py. Each has attributes t_send: float, t_first: float | None, t_end: float, outcome: str in ("completed", "cancelled", "failed"). All timestamps share the perf_counter clock.

Output shapes must equal the 02-04 sidecar schema keys:
- requests block: {sent, completed, cancelled, failed, ttft_ms: {p50, p90, p99, max}, rps}
- gc block per role: {count, by_generation: {"0", "1", "2"}, total_pause_ms, pause_ms: {p50, p99, max}, collected, events: [[t_rel_s, duration_ms, generation]]}
- correlation: {p99_ttft_ms, spike_requests, spike_with_gc, nonspike_requests, nonspike_with_gc, spike_overlap_rate, nonspike_overlap_rate}
- memory per role: {rss_bytes: {start, end, max, growth}, rss_curve, tracemalloc: {current_start, current_end, peak}, tracemalloc_curve, top_alloc_sites}
- cpu per role: {active_samples, gil_samples, window_s, rate_hz, cpu_active_pct, gil_held_pct, buckets: {name: {samples, share_of_active, per_request_ms}}}
- radix: {radix_samples, scheduler_samples, share}
Bucket names (sidecar.REQUIRED_BUCKETS): radix, ipc_zmq, serde, tokenize, detokenize, http_stack, api_handlers.
