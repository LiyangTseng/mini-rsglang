<objective>
Build and pre-flight-test the zero-touch in-process instrumentation that D-02 (tracemalloc) and D-03 (gc.callbacks pause timing) need inside the api_server, scheduler and tokenizer processes, without editing any vendored file.

Purpose: RESEARCH Pitfall 3 / Assumption A1 is the one load-bearing unverified assumption of the D-02/D-03 design. The question is whether a startup hook propagates into processes that minisgl starts with multiprocessing spawn, and across rsglang.launch's os.execv. RESEARCH Open Question 2 asks for a cheap, Mac-testable pre-flight check to run before any other work commits to that design. Task 1 is that check, shaped as this plan's tracer. Nothing else in the phase builds on the hook until it passes.

Design choice (Claude's discretion per CONTEXT: "the precise gc.callbacks wiring"). The hook enters as a generated `sitecustomize.py` in a per-run directory placed first on PYTHONPATH, gated by RSGLANG_PROFILE_DIR. RESEARCH proposed a `.pth` file in the venv's site-packages instead. Both rely on the same `site`-module startup step (site imports sitecustomize right after processing .pth files), and both reach spawn children the same way, through inherited environment variables. The sitecustomize route was chosen because it never writes into the venv. Nothing persists after a run, which removes RESEARCH's "hook left installed after the phase" threat by construction rather than by a cleanup step. If an existing sitecustomize is shadowed, the shim chain-loads it.
Output: python/rsglang/profiling/{__init__,hook}.py and python/tests/test_profile_hook.py.
</objective>

- JSONL record shapes. One JSON object per line, and every record has "kind" and "pid":
  start: {"kind":"start","pid":int,"ppid":int,"orig_argv":[str],"t":float,"wall":float,"clock":str}
  gc: {"kind":"gc","pid":int,"t":float,"duration_s":float,"generation":int,"collected":int,"uncollectable":int}. t is time.perf_counter() at GC stop.
  mem: {"kind":"mem","pid":int,"t":float,"traced_current":int,"traced_peak":int}
  alloc_top: {"kind":"alloc_top","pid":int,"t":float,"tag":str,"sites":[{"file":str,"line":int,"size_bytes":int,"count":int}]}
- Every t is time.perf_counter(). On Linux that is CLOCK_MONOTONIC, a system-wide clock that the driver's request timestamps share. "clock" is time.get_clock_info("perf_counter").implementation.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-04 | Denial of Service | hook code raising inside the profiled server | medium | mitigate | gc callback only appends to a deque; thread body, atexit flush, install() call in the shim and chain-load are each wrapped so no exception escapes into the host process |
