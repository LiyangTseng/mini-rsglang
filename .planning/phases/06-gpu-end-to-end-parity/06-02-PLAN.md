<objective>
Build D-12's process-health watcher: a separate, thin bash script that follows `scripts/gpu_phase1_check.sh`'s conventions. It watches the scheduler process around the 128-request cancellation stress run and reports crash, zombie or restart states. Plan 06-05 starts it around each stress run against the real backend.

Purpose: criterion 4 requires the stress run to finish "without crashing or wedging the scheduler". D-12 keeps crash detection out of Phase 5's stress tool, which is reused unchanged per D-11, and puts it where the GPU verification scripts already live. RESEARCH Pitfall 2 warns that liveness alone can false-PASS on silent corruption. That second signal comes from the backend tap (plan 06-01), analyzed in plan 06-05. This watcher covers the process half.

Output: `scripts/gpu_phase6_watch.sh` and `python/tests/test_gpu_phase6_watch.py`.

Layout choice (CONTEXT Claude's discretion: "new script vs. extending gpu_phase1_check.sh's pattern"): this is a new script. The three helpers follow gpu_phase1_check.sh's semantics exactly. gpu_phase1_check.sh itself is not modified. It is Phase 1's signed-off GPU artifact, and sourcing it would run its argument parsing and mktemp. Copying three small helpers follows Phase 2's precedent: gpu_phase2_profile.sh defines its own `record` too.

Detection lives here, never in Phase 5's stress tool (D-11/D-12). Started and stopped by scripts/parity_check.py's stress part."
- `set -euo pipefail`, then usage() as a heredoc in the Interfaces CLI form, and an argument loop in gpu_phase1_check.sh's style:
  - `--pid` requires a value matching ^[0-9]+$, else exit 2;
  - `--interval` defaults to 1;
  - `--out` and `--launcher-log` are optional;
  - `--help` or `-h` prints usage and exits 0;
  - an unknown argument or a missing --pid prints usage to stderr and exits 2.
- Helpers defined before the source guard, so tests can source the file:
  - `alive`, `gpu_pids` and `on_gpu`, with gpu_phase1_check.sh lines 106-114's exact semantics;
  - `proc_state <pid>` prints the first character of `ps -o stat= -p <pid>` with whitespace stripped, or "gone" when ps prints nothing;
  - `scheduler_spawns <log>` prints the number of lines matching 'spawned scheduler rank=0 pid=' in the file, and 0 when the file is missing.
- The source guard is copied from gpu_phase1_check.sh lines 160-164.
- Main body:
  - Counters samples, crashed, zombie, restarts, gpu_unlisted and nvsmi_errors all start at 0.
  - STOP=0, with `trap 'STOP=1' TERM INT`.
  - Loop while STOP is 0:
    - state=$(proc_state "$PID").
    - gpu: `rc=0; on_gpu "$PID" || rc=$?`. rc 0 means listed. rc 1 means unlisted (gpu_unlisted+1). rc 2 means nvsmi_error (nvsmi_errors+1) and is never counted as listed.
    - Append the sample line to --out if it is set, and increment samples.
    - If state is "gone", set crashed=1 and break. If state is "Z", set zombie=1 and break.
    - If --launcher-log is set, restarts = max(scheduler_spawns - 1, 0).
    - Sleep the interval in 0.1 s slices, checking STOP each slice, so a SIGTERM ends the loop within about 0.2 s.
- After the loop, the verdict is unhealthy iff crashed=1, zombie=1 or restarts>0. Print the summary line to stdout and append it to --out. Exit 0 when healthy, 1 when unhealthy.

Tests in python/tests/test_gpu_phase6_watch.py, with `pytestmark = pytest.mark.slow`. Use a stub `nvidia-smi` whose body prints the value of env STUB_GPU_PIDS, one pid per line, for `--query-compute-apps`, and "Fake GPU" otherwise.
