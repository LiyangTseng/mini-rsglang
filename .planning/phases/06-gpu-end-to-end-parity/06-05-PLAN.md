<objective>
Re-run the 128-request cancellation stress test against the real backend (ROADMAP criterion 4, D-11). Surround it with D-12's watcher and the backend tap, and add a backend-level window probe, so this phase can settle empirically whether the suspected abort-during-prefill double free reproduces, under which trigger, and with which failure mode (D-08).

Purpose: RESEARCH found a concrete mechanism. `_free_req_resources` runs unguarded from the abort branch (scheduler.py lines 190-195), while the natural-finish path's guard (line 159) relies on `finished_reqs`, which aborts never populate. `TableManager.free` appends a slot twice with no check. The predicted symptom is silent corruption of an unrelated request, not a crash.

A process watcher alone would false-PASS that case (Pitfall 2). The tap gives direct evidence instead: two free records for one uid, a duplicated free slot, or two live uids sharing a table slot.

There is a second gap. The frontends only notice a disconnect at their next write, so Phase 5's stress tool may never land an abort inside the prefill window. The direct backend probe closes that gap: it exercises the window deliberately. The `conclusive` flag records whether the window was ever hit.

Output:
- new modules stress.py, abort_analysis.py and probe.py;
- the `stress` run part and verdict 4;
- fake-server stress knobs and a fake stress driver;
- annotate_sequence wired into the sequential part.
</objective>
