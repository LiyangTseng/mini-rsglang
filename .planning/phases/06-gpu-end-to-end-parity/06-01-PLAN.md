<objective>
Build the parity measurement path end to end: a fresh session per frontend, a one-at-a-time HTTP sweep, backend-side token-id ground truth, an ids-first comparison, and a validated sidecar. Then make the backend tap real inside the vendored scheduler.

Purpose: PAR-01's hard gate compares token ids first (D-06). Neither frontend's HTTP response carries ids (RESEARCH Pitfall 1: UserReply has no token_ids). This plan captures them once, in the shared backend, for both frontends. An env-gated in-process tap wraps the scheduler's message intake (UserMsg input_ids and sampling params) and its reply path (DetokenizeMsg next_token). It also records the free, abort and batch-slot events that plan 06-05 needs to decide D-08.

Deviation from the RESEARCH recommendation, under CONTEXT's Claude's-discretion item on internal layout and RESEARCH Open Question 3. RESEARCH proposed two taps: a one-line log in vendored scheduler.py plus a Rust debug dump. This plan uses one tap instead: a generated sitecustomize shim, the same mechanism as Phase 2's profiling hook (python/rsglang/profiling/hook.py), which never touches vendor/. The reasons:
1. Project precedent keeps the vendored tree pristine. Phase 1 D-09 did the handshake as a wrapper, and Phase 2's hook is a shim. Any listed vendored modification also makes `scripts/check_upstream.py --offline` and therefore `scripts/check_all.sh --offline` unusable.
2. CONTEXT's phase boundary says Phase 5's Rust frontend is consumed unmodified.
3. The scheduler sees every UserMsg and DetokenizeMsg of either frontend, so one tap is the shared ground truth D-06 describes.
4. It also captures input_ids, which D-05's bisection needs to separate tokenization from backend divergence.

Second deviation, for the HTTP client. RESEARCH's "Don't Hand-Roll" table and CONTEXT's canonical refs point at bench_simple.py's AsyncOpenAI client. The sweep uses aiohttp instead: aiohttp 3.14.4 is in the hashed Mac lock and Phase 2's drivers already use it, whereas `openai` is not in requirements-mac.txt and would need a new package-legitimacy gate on the Mac. The sweep sends non-streaming JSON requests, so no SSE parser is hand-rolled. The endpoint checks in 06-04 only assert framing lines.

Output: the `rsglang.parity` package (tap, corpus, compare, sidecar, sweep), `scripts/parity_check.py` (run, validate), the Mac stand-in `rsglang.testing.fake_parity_server`, and tests.
</objective>
